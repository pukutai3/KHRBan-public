## 学習方式

起き上がりは速度追従とは別の方策・ログ系列 (`khr_getup`) とする。ロボットモデルやBAMアクチュエータは共有し、速度追従環境を土台にKHRの関節対応、18関節制御、観測ノイズ／遅延、足裏摩擦、エンコーダバイアス、重心・慣性・関節摩擦のランダム化を維持する。コマンド、速度追従報酬、歩行中の転倒終了、ランダムな押し外乱は起き上がり環境から外す。

腰ヨー、首ヨー、左右肘ヨーはホーム位置のまま固定し、行動対象にしない。方策側は基底角速度、重力方向、18関節位置／速度、直前行動、脚屈伸率を使う。シミュレーションでのみ取得できる並進速度、胴体高さ、接地状態はcritic／評価側に限り、actorには渡さない。

行動目標はサンプルモーション由来のKHR角度エンベロープ内に制限する。この値は機械的可動限界を意味しない。起き上がり専用報酬は姿勢の直立化、実測ホーム姿勢の胴体高さへの進行、直立後の両足支持、不要なホーム姿勢逸脱・関節速度・行動変化・トルクの抑制で構成する。

## 開始姿勢とKHR寸法

MuJoCoで実KHR衝突形状、確認済みHTH4ホーム角、平面床を使って測った値。角度はURDF基底軸からのEuler角で、ヨーは0°固定。ルート高さには干渉を避ける約2 mmの離隔を含む。

| 開始クラス | roll | pitch | root高さ |
|---|---:|---:|---:|
| 顔を床へ向けた姿勢 | 0° | +90° | 83 mm |
| 背中を床へ向けた姿勢 | 0° | −90° | 70 mm |
| 左側面を床へ向けた姿勢 | −90° | 0° | 122 mm |
| 右側面を床へ向けた姿勢 | +90° | 0° | 103 mm |

確認済みホーム姿勢の胴体リンク `c_chest_c_1` の高さは304.75 mm。評価の270 mm下限はこのKHRモデルから導出した。この候補の開始姿勢はヨー0°に限定しているため、ヨーを含む全方位の転倒回復はまだ合格範囲に含めない。

## 評価と継続

評価は固定seedで4クラスを均等に割り当て、各クラスを個別集計する。最後の1秒（50 Hzで50ステップ）を通して、胴体高さ270 mm以上、直立cos値がcos(20°)以上、左右両足が接地している環境だけを成功とする。平均値で難しい姿勢を隠さないよう、4クラスすべてが80%以上でない限り不合格とする。

`khrban-auto-train-getup` は速度追従の現在の自動学習系列について、`achieved=true` の正式評価記録と実在するチェックポイントの両方を確認してから起動する。速度追従と起き上がりは同じ排他ロックを使い、同時にGPU学習・評価を行わない。不合格なら2,000反復ずつ無制限に追加学習し、起き上がりログ内の最新3チェックポイントを残す。評価記録・TensorBoardログは削除しない。

```bash
uv run khrban-auto-train-getup --check-velocity-gate
uv run khrban-auto-train-getup --num-envs 1024 --iterations-per-round 2000 \
  --eval-num-envs 256 --eval-num-steps 500 --live-viewer \
  --viewer-num-envs 16 --viewer-port 8080 --keep-checkpoints 3
```

Control Deskの「起き上がり開始」ボタンも同じゲートと学習監督を使う。押下時に速度追従評価を再確認し、合格していなければ開始を拒否する。既存の「速度追従歩行」ボタンは残し、両方を別の開始操作・別の確認ダイアログにする。学習中ビューアは従来のMicroban互換経路と同じく、PPOが実際に更新している環境のうち16体を表示する。

この作業ではGPU学習を開始しない。速度追従の評価合格後にボタンから開始できる状態を目指し、実際の学習成果・GPU負荷・可視化・4姿勢の達成はその時点で別途検証する。
